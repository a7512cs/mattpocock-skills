# MISSION.md 格式 (MISSION.md Format)

`MISSION.md` 放在工作區根目錄。它記錄使用者學習這個主題的*原因*。每個教學決定（下一步教什麼、要提出哪些資源、要設計哪些練習）都應該能追溯回這份文件。

## 範本 (Template)

```md
# Mission: {主題}

## Why
{1 到 3 句話。使用者追求的具體真實世界目標。當他們擁有這項技能時，他們的生活或工作會有什麼改變？避免像「為了理解 X」這種抽象的說法；要追問背後真正的結果。}

## Success looks like
- {使用者將能做到的一件具體、可觀察的事}
- {另一件具體的事}
- {…}

## Constraints
- {時間、預算、既有承諾、學習偏好，任何限制做法的因素}

## Out of scope
- {使用者明確表示現在不想追的相鄰主題，用來保護近側發展區}
```

## 規則 (Rules)

- **每個工作區一個使命**（mission）。如果使用者想學兩件不相關的事，那就是兩個工作區。
- **具體勝過抽象**。「十月前跑完半程馬拉松」勝過「變得更健康」。「交付一個 Rust CLI 給我的團隊」勝過「學 Rust」。
- **對模糊說法提出反駁**。如果使用者說不出為什麼，在寫任何東西之前先訪談他們。糟糕的使命比沒有使命更糟。
- **現實改變時就修訂**。使命會變。當使用者的目標移動時，更新這個檔案：不要讓過時的使命繼續引導未來的 session（工作階段）。
- **保持簡短**。如果 `MISSION.md` 超過一個畫面，它就不再是指南針，而開始變成計畫了。
