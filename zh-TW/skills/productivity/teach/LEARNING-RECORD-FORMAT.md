# 學習紀錄格式 (Learning Record Format)

學習紀錄放在 `./learning-records/`，使用連續編號：`0001-slug.md`、`0002-slug.md` 等等。延遲建立這個目錄：只在寫下第一筆紀錄時才建立。

它們是 ADR（架構決策紀錄）在教學上的對應物：記錄不明顯的教訓、關鍵洞見，以及使用者自述的先備知識，這些都會引導未來的 session（工作階段）。它們用來計算近側發展區（zone of proximal development）。

## 範本 (Template)

```md
# {所學到或確立之事的簡短標題}

{1 到 3 句話：學到了什麼（或確立了什麼先備知識），以及它為什麼對未來的 session 很重要。}
```

這就是整個格式。一筆學習紀錄可以只有一段話。價值在於記錄*這件事*現在已經知道了，以及它*為什麼*改變下一步要教的內容，而不是在於填寫各個區段。

## 選用區段 (Optional sections)

只在它們能帶來真正價值時才加入。大多數紀錄都不需要。

- **Status** frontmatter（檔頭中繼資料，值為 `active | superseded by LR-NNNN`）：當早先的理解後來發現是錯的、並被取代時很有用。
- **Evidence**（證據）：使用者如何展現這份理解（回答了一個問題、完成了一個練習、提到過去的經驗）。當這個主張之後可能被重新檢視時很有用。
- **Implications**（影響）：這為未來的 session 解鎖或排除了什麼。不明顯時值得記錄。

## 編號 (Numbering)

掃描 `./learning-records/`，找出現有的最大編號，再加一。

## 什麼時候寫學習紀錄 (When to write a learning record)

當以下任一項成立時，就寫一筆：

1. **使用者展現出對某個不簡單事物的真正理解**：不只是接觸過，而是有證據顯示他們能正確使用這個概念。這為下一步要教的內容設下新的底線。
2. **使用者透露了先備知識**：「我已經知道 X。」記錄下來，讓未來的 session 不會重教。也要記錄他們聲稱的*深度*。
3. **一個誤解被糾正了**：使用者之前相信某件錯的事，現在明白為什麼錯。這些價值很高：它們能預測相關主題未來的絆腳石。
4. **使命（mission）因學習而轉移**：使用者發現自己在乎的東西和原本想的不一樣。交叉連結到 [[MISSION.md]] 並更新它。

### 什麼*不*算 (What does _not_ qualify)

- 只是講過的內容。講過不等於學會。等待證據。
- 任何已經以術語定義的形式，簡潔記錄在 [[GLOSSARY.md]] 裡的東西。不要重複。
- 每次 session 的活動日誌。學習紀錄不是日記：它們是足以支撐決策的洞見。

## 取代 (Supersession)

當後來的紀錄和早先的紀錄矛盾時（使用者的理解加深了或被修正了），把舊紀錄標記為 `Status: superseded by LR-NNNN`，而不是刪除它。理解如何演變的歷史，本身就是有用的訊號。
